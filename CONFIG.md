# Config files

Root-level config files, nested under this doc in the VS Code Explorer (see `.vscode/settings.json` → `explorer.fileNesting.patterns`) purely to keep the project root uncluttered. This file is what they're nested under instead of `package.json`, since documenting them is a better fit for "parent" than an arbitrary pick of one config among several.

- **package.json** — npm manifest: scripts (`dev`, `build`, `start`, `lint`, `format`) and dependencies (Next.js, React, `@supabase/supabase-js` + `@supabase/ssr`); devDependencies are Tailwind v4, TypeScript, ESLint, Prettier + `prettier-plugin-tailwindcss`, `@playwright/test` (used ad hoc to drive the real UI while testing, not a committed test suite).
- **package-lock.json** — npm-generated dependency lockfile. Don't hand-edit.
- **tsconfig.json** — TypeScript compiler config: strict mode, bundler module resolution, `@/*` path alias to `src/`.
- **tsconfig.tsbuildinfo** — auto-generated incremental build cache from `tsc`. Gitignored; safe to delete, regenerates on next build.
- **next.config.ts** — Next.js config; pins `turbopack.root` to this project directory so Turbopack stops guessing the workspace root because of the unrelated `package-lock.json` in your home directory.
- **next-env.d.ts** — auto-generated Next.js TypeScript declarations. Gitignored; regenerated by `next dev`/`next build`, don't edit by hand.
- **eslint.config.mjs** — ESLint flat config, extending `eslint-config-next`'s core-web-vitals and typescript rule sets.
- **postcss.config.mjs** — PostCSS config wiring up the Tailwind v4 PostCSS plugin.
- **.prettierrc** — Prettier config; loads `prettier-plugin-tailwindcss` so `className` strings get their utility classes auto-sorted into Tailwind's canonical order on format. VS Code is wired to format-on-save via `.vscode/settings.json` (`editor.defaultFormatter`/`editor.formatOnSave`); `npm run format` runs it across the whole project manually.
- **.gitignore** — standard Next.js ignores (`node_modules`, `.next`, build artifacts) plus env files (all `.env*` ignored except `.env*.example`, so the real Supabase credentials never get committed).
- **.env.local** — local Supabase credentials (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`). Gitignored, never committed.
- **.env.local.example** — template documenting the required env vars for `.env.local`, without real values.
